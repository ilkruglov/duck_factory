# Список изменений

Что менялось для пользователя в каждой версии duck-factory. Оба плагина — для Claude Code (`plugins/duck-factory`) и
для Codex (`plugins/duck-factory-codex`) — с 0.2.0 носят одну версию, кроме 0.2.1: она меняла только плагин для
Claude Code. Замеры и причины целиком — в сообщениях коммитов. По-английски: [CHANGELOG.md](CHANGELOG.md).

## 0.4.2 - 2026-11-24

- В Claude Code `review` запускает новый состав ревьюеров, выбранный по замеру на двух настоящих правках с 22 важными
  ошибками, известными по поздним исправлениям; каждая находка проверена по коду. Codex всегда получает задание
  навыка на всё изменение вместо собственного ревью; начиная с обычной ступени рядом идёт его «адвокат дьявола» с
  прицелом, который агент пишет по диффу; со стороны Claude — встроенный `/code-review` на всё изменение: `low` на
  лёгкой правке, `medium` на обычной, `high` на усиленной или при нескольких группах. Субагенты Claude по группам
  файлов теперь идут только в финальном ревью. Втроём они нашли 19 из 22 важных ошибок за 12,4M токенов Claude;
  прежний состав для большой правки — 18 за 81,5M. У задачи Codex с заданием на всё изменение 30 минут вместо 15:
  на большой правке она идёт дольше.
- В повторном круге субагент Claude идёт на уровне `medium`. Субагенты Claude запускаются без указания
  модели и поэтому идут на модели сессии. Без Codex встроенное ревью идёт на уровень выше
  (`high` остаётся `high`), а вне финального ревью правка в несколько групп получает ещё одного субагента Claude с
  заданием на всё изменение.
- Шаг упрощения в конце `review` больше не запускает `/simplify`. В Claude Code Codex перечисляет упрощения, ничего
  не меняя, а агент тем временем сам проходит дифф; агент отбрасывает вкусовщину, то, что меняет поведение или
  задевает код вне правки, и применяет остальное вместе со своим. В Codex агент делает это сам. Направления те же,
  что у `/simplify`, — повторное использование, повторы и мёртвый код, лишняя работа, частные случаи там, где надо
  поменять общее правило, — а в текстах навыков и документации повторы и противоречия правил. На двух законченных
  правках Codex и агент вместе нашли 31 из 37 настоящих упрощений; `/simplify` — 17 за вчетверо больше токенов Claude
  и в одной из них поменял поведение.

## 0.4.1 - 2026-11-23

Короткие повторные круги в `review`. В одном проекте две задачи за два дня прошли 18 кругов ревью по 30–60 минут:
после каждой мелкой правки снова целиком ревьюилось всё изменение.

- Повторный круг после исправлений проверяет только исправленные места: сам фикс, код, который его вызывает, код,
  который вызывает он, и тесты. Список исправленных мест ведёт сам агент.
- Ревьюеры повтора — по тому, где исправления: в Claude Code одна задача Codex и один субагент Claude на каждую группу,
  где чинили (без Codex — только субагент), в Codex — один субагент на группу.
- Отчёт называет рядом с каждой подтверждённой ошибкой места, где повторяется та же логика; «да» покрывает их, а ту же
  ошибку, найденную где-то ещё, сначала показывают пользователю.
- Пока чинят — идут только тесты исправленного места; полный набор — один раз за круг.
- Шаг упрощения (`/simplify` в Claude Code, сам агент в Codex; для текстов навыков и документации — один субагент) —
  один раз, в конце; затем тесты и одна проверка, что поведение не изменилось.
- После третьего повторного круга навык останавливается и спрашивает: продолжать, упростить подход или принять
  остаток — и говорит, сколько настоящих ошибок принёс каждый круг.
- `grill` сначала спрашивает, закоммитить ли принятую, но не закоммиченную работу другой задачи, чтобы ревью новой
  задачи читало только новую правку.

## 0.4.0 - 2026-11-23

- Задания ревьюеров групп и прохода безопасности велят прочитать правила проекта (в Claude Code `CLAUDE.md`,
  `.claude/rules/` и подобные; в Codex `AGENTS.md`) и сообщать о правке, которая их нарушает.
- Проход безопасности — только после «да» пользователя или сразу, если пользователь сам о нём попросил: предлагается
  раз на работу на финальном ревью и когда правка задевает путь из списка `Security paths`; ищет только достижимые
  уязвимости и ставит каждой уровень critical, high, medium или low. Сканеры безопасности в него не входят: плагин
  Codex Security не запустил проверку изменений три раза из трёх, а Claude Security проверяет только закоммиченное.
- «Да» покрывает только находки, которые пользователь видел; вопросы в конце отчёта пронумерованы.
- Падающий тест исправления должен падать на самой ошибке, а не на импорте или опечатке.
- Шаг упрощения для текстов навыков, промптов и документации — один субагент (вместо `/simplify` в Claude Code).
- `grill` берёт уже принятое решение из решений прошлого принятого плана или из правил проекта, со ссылкой, вместо
  того чтобы спрашивать снова; если два плана расходятся, спрашивает.
- Стенд читает файлы частями: большой файл, оставленный агентом, больше не съедает всю память.

## 0.3.0 - 2026-11-20

- Финальное ревью всего, что сделано с начала работы, — перед PR, слиянием или выпуском: на настоящем форке одно
  ревью всей правки нашло восемь ошибок, которые пропустили пошаговые.
- На обычной и усиленной ступени большая правка делится по подсистемам на группы, до четырёх; в Claude Code на каждую
  группу — задача Codex и свежий субагент Claude, в Codex — один субагент. Правка, которая умещается в одну группу,
  остаётся со встроенным ревью и Codex.
- Codex берёт модель из своих настроек, а не зашитую; `review` отдаёт задания в Codex файлом.
- «Необратимо» — про то, что правка делает с уже существующим, а не про то, что новая функция позволит потом.
- `grill` для Codex спрашивает по режиму: в Plan mode — `request_user_input`, иначе асинхронными инструментами и всегда
  повторяет вопросы в итоговом сообщении.

## 0.2.1 - 2026-11-18

- Возобновлённая сессия получает имя активного плана, а не весь текст: текст возвращался при каждом возобновлении и
  стоил по две-три тысячи токенов. После сжатия план по-прежнему возвращается целиком, если умещается в 8000 символов.
- README на русском рядом с английским.

## 0.2.0 - 2026-11-18

- `grill` сначала спрашивает, какие задачи делать вообще, когда набор задач одобрен оптом или предложен агентом; в
  планах есть `Status` и `Source`; работает и для задач без кода.
- `review` считает строки без правок одних отступов (файл, где поменялись только отступы, всё равно считается),
  считает кодом файл данных, который читает код, берёт ступень только из таблицы и перед отчётом убирает то, что
  создал вне `.tmp/`.
- Хуки для Claude Code: перед сжатием сводку просят сохранить точные команды, непроверенное, согласия и поправки
  пользователя; после сжатия или возобновления активный план возвращается целиком (план длиннее 8000 символов только
  называется).
- `evals/bench.py`: синтетический проект с посеянными ошибками, на котором гоняются навыки в Claude Code или Codex.

## 0.1.1 - 2026-11-11

- `grill` до первого вопроса подгружает навыки, которые покрывают область задачи, и называет их в плане.
- Подробный README: как идёт сессия, как выбирается ступень, пример отчёта, время и стоимость.
- В тот же день: версия плагина для Codex (своя 0.1.0) — три навыка внутри Codex, каждая проверка в субагенте со
  свежим контекстом (в самой сессии, если субагенты недоступны, и отчёт об этом говорит).

## 0.1.0 - 2026-11-11

- Три навыка: `grill` (договориться о нетривиальной задаче до кода, с планом на страницу), `review` (одно ревью кода
  со ступенью, измеренной по правке, встроенным ревью и Codex параллельно, каждая находка разобрана до отчёта и
  отмечена: подтверждена, не подтверждена или не проверена) и `handoff`
  (файл, который свежая сессия сверяет с реальностью, прежде чем продолжить).
